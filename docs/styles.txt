26:T780,GPT-Vis is an open-source visualization library for AI agents and applications. It renders 26 types of visualization from a small JSON configuration or readable Syntax, including statistical charts, relationship graphs, tables, and text summaries.

## Choose a starting point

- **Use an agent:** install the [chart-visualization Skill](/docs/agent-skill) to choose charts, generate configurations, and create reusable themes.
- **Build an application:** follow the [SDK quickstart](/docs/quickstart) to render your first chart in JavaScript or TypeScript.
- **Explore the output:** browse [chart examples](/examples) or switch themes in the [homepage gallery](/#charts).

## One theme across your visualizations

The `theme` option accepts shared colors, typography, and supported style settings. Use the same object for statistical charts, relationship graphs, tables, and summaries. Explore the [theme gallery](/themes), download its JSON, or ask your agent to create a theme from your brand references.

Custom theme objects are available from **@antv/gpt-vis 1.3.0**. Use gallery presets by their built-in names, such as `pop` or `midnight`. For a customized style, pass the complete JSON object. See [themes and supported names](/docs/themes).

## Model output, rendered as it arrives

GPT-Vis accepts both [JSON and Syntax](/docs/syntax). For streaming responses, pass the accumulated Syntax to the same instance as more text arrives. See [streaming rendering](/docs/streaming).

## What GPT-Vis handles

Your application supplies the data and analysis results. GPT-Vis handles rendering, chart defaults, visual styling, and supported chart interactions. Querying databases, forecasting, and explaining business causes belong in the agent or application that uses it.

The same `render()` method accepts a Syntax string. Choose the format that fits your model or application.

```typescript
chart.render(`vis line

data
  - time Jan
    value 12000
  - time Feb
    value 18000
  - time Mar

```

## Reuse a theme

Download a JSON file from [Theme Studio](/themes), then pass it to the constructor. The instance keeps that theme across subsequent `render()` calls.

```typescript
import { GPTVis, type ThemeSpec } from '@antv/gpt-vis';
import theme from './my-theme.json';

const chart = new GPTVis({
  container: '#chart',
  theme: theme as ThemeSpec,
});

chart.render({ type: 'line', data });
// A later render can use another chart type with the same theme.
chart.render({ type: 'table', data });
```

Each instance renders into one container. To show several charts at once, create an instance for each container and reuse the same theme object.

## Equivalent Syntax

Start with `vis` and the chart type. Indentation describes nested objects and array items.

```text
vis line
title Monthly revenue
data
  - time Jan
    value 120
  - time Feb
    value 180
  - time Mar
    value 150
```

Pass the string directly to `chart.render(syntax)`. During streaming, send the full accumulated Syntax buffer on each update; see [streaming rendering](/docs/streaming).

## Values and nesting

- Write a property as `key value` or `key: value`.
- Use `-` for array items and indentation for their properties.
- Quote text containing spaces. Quoted values stay strings, including `"2026"` and `"true"`.
- Indent `children` under its parent item for hierarchical charts.
- Put visual overrides under `style`; keep data and layout options at their documented level.

```text
vis mindmap
data
  - name "Project plan"
    children
      - name Research
        children
          - name "Market analysis"
          - name "Feasibility study"
      - name Development
```

## Chart-specific data shapes

Different charts use different field names. For example, line charts use `time` and `value`; bars and columns use `category` and `value`; network graphs use `nodes` and `edges`.

```text
  - "North America"
  - "Southeast Asia"
  - Europe
series
  - type line
    name Revenue
    data
      - 100
      - 120
      - 90
  - type column
    name Units
    data
      - 50
      - 60
      - 45
```

Use the [chart reference](/docs/charts) to find a complete example for your data shape.

When your model produces Syntax in chunks, call `render()` with the **entire accumulated buffer**. Keep one GPTVis instance for the container so it can update the chart as more data arrives.

## Connect a token stream

```typescript
import { GPTVis, isVisSyntax } from '@antv/gpt-vis';

const chart = new GPTVis({ container: '#chart' });
let buffer = '';

function onToken(token: string) {
  buffer += token;
  if (isVisSyntax(buffer)) chart.render(buffer);
}

// Connect onToken to your model client's stream callbacks.
// When the view unmounts, stop the stream and call chart.destroy().
```

`isVisSyntax()` checks the `vis` prefix. It is not a schema validator. The renderer tolerates incomplete Syntax while a response is arriving; the chart becomes useful as its required fields and data become available.

## JSON responses

A complete JSON configuration can go straight to `render()`. Incomplete JSON text is not a configuration object: collect it until it can be parsed, or use your model client’s structured-output parser before rendering an object. Prefer Syntax when you want to render incremental plain-text output.

## Rendering cadence and cleanup

For a fast stream, batch updates at the application level so a large chart is not redrawn for every character. Always pass the accumulated result, rather than only the newest token. Stop the stream when the view closes, and call `destroy()` to release the chart.

A theme belongs to the instance and is reused during updates. It does not need to be included in every token or render call.

## How overrides work

Appearance is resolved in this order, with later values taking priority:

**Built-in defaults → tokens → shared style → chart-specific style → per-render style**.

Nested objects merge; arrays replace. A `theme` in the render configuration takes priority over the constructor theme. This lets an individual chart choose a different appearance. Summary uses its constructor theme with T8 text and has no per-render style object.

For relationship graphs, a fixed `style.node.fill` or `charts['network-graph'].style.node.fill` overrides category colors. Leave fixed node fills out when nodes should use the shared palette.

## React

In Next.js, keep this wrapper in a Client Component. The example creates one instance per mount and reuses it when the Syntax changes.

```tsx
'use client';

import { GPTVis } from '@antv/gpt-vis';
import { useEffect, useRef } from 'react';

export function Chart({ syntax }: { syntax: string }) {
  const container = useRef<HTMLDivElement>(null);
  const chart = useRef<GPTVis | null>(null);

  useEffect(() => {
    if (!container.current) return;
    chart.current = new GPTVis({ container: container.current });
    return () => {
      chart.current?.destroy();
      chart.current = null;
    };
  }, []);

  useEffect(() => {
    if (syntax) chart.current?.render(syntax);
  }, [syntax]);

  return <div ref={container} style={{ height: 360 }} />;
}
```

```typescript
interface ThemeSpec {
  id: string;
  label: string;

  baseTheme?: string;
```

| `colorDefault`                                        | Primary series or emphasis color                    |
