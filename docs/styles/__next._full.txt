2b:T807,GPT-Vis is an open-source visualization library for AI agents and applications. It renders 26 types of visualization from a small JSON configuration or readable Syntax, including statistical charts, relationship graphs, tables, and text summaries.

## Choose a starting point

- **Use an agent:** install the [chart-visualization Skill](/docs/agent-skill) to choose charts, generate configurations, and create reusable themes.
- **Build an application:** follow the [SDK quickstart](/docs/quickstart) to render your first chart in JavaScript or TypeScript.
- **Explore the output:** browse [chart examples](/examples) or switch themes in the [homepage gallery](/#charts).

## One theme across your visualizations

The `theme` option accepts shared colors, typography, and supported style settings. Use the same object for statistical charts, relationship graphs, tables, and summaries. Explore the [theme gallery](/themes), download its JSON, or ask your agent to create a theme from your brand references.

Custom theme objects are available from **@antv/gpt-vis 1.3.0**. Use gallery presets by their built-in names, such as `pop` or `midnight`. For a customized style, pass the complete JSON object. See [themes and supported names](/docs/themes).

## Model output, rendered as it arrives

GPT-Vis accepts both [JSON and Syntax](/docs/syntax). For streaming responses, pass the accumulated Syntax to the same instance as more text arrives. See [streaming rendering](/docs/streaming).

## What GPT-Vis handles

Your application supplies the data. GPT-Vis handles rendering, chart defaults, visual styling, and supported chart interactions. Its [28 analysis annotations](/docs/annotations) calculate supported summaries such as rankings, means, and crossings and display them in supported charts. Querying databases, forecasting, and explaining business causes belong in the agent or application that uses it.

## Create your first chart

After installation, start a new agent session if your tool requires it. Try this task with a small, fixed dataset:

```text
Use the GPT-Vis chart-visualization skill to create a monthly revenue report from these values (USD): Jan 12000, Feb 18000, Mar 15000, Apr 24000.

Include a line chart, a table with the same four values, and a short summary of the total revenue and April's change from March. Calculate the figures from the supplied data.

```

The deliverables should contain the same four values, with matching visual styling. Open the generated HTML in your browser, or import its theme JSON into [Theme Studio](/themes) to compare it across chart types.

## Create a theme from a reference

Give your agent a website, slide, brand guide, or visual reference and ask it to follow the bundled Theme Creator reference. Request a theme JSON object that works across statistical charts, relationship graphs, tables, and text summaries.

Keep category colors in the palette. A fixed `style.node.fill`, or a fixed node fill in a relationship chart override, can replace palette colors and make every node look the same. Use one only when that uniform appearance is intentional.

Add a visible container to your page, then create the instance after the container is mounted. GPT-Vis renders in the browser.

const chart = new GPTVis({

chart.render({

  title: 'Monthly revenue (USD)',
  data: [
    { time: 'Jan', value: 12000 },
    { time: 'Feb', value: 18000 },
    { time: 'Mar', value: 15000 },
    { time: 'Apr', value: 24000 },
  ],
});

## Use Syntax instead

The same `render()` method accepts a Syntax string. Choose the format that fits your model or application.

```typescript
chart.render(`vis line
title Monthly revenue (USD)
data
  - time Jan
    value 12000
  - time Feb
    value 18000
  - time Mar
    value 15000
  - time Apr
    value 24000`);
```

## Reuse a theme

Download a JSON file from [Theme Studio](/themes), then pass it to the constructor. The instance keeps that theme across subsequent `render()` calls.

```typescript
import { GPTVis, type ThemeSpec } from '@antv/gpt-vis';
import theme from './my-theme.json';

const chart = new GPTVis({
  container: '#chart',
  theme: theme as ThemeSpec,
});

chart.render({ type: 'line', data });
// A later render can use another chart type with the same theme.
chart.render({ type: 'table', data });
```

Each instance renders into one container. To show several charts at once, create an instance for each container and reuse the same theme object.

## Equivalent Syntax

Start with `vis` and the chart type. Indentation describes nested objects and array items.

```text
vis line
title Monthly revenue
data
  - time Jan
    value 120
  - time Feb
    value 180
  - time Mar
    value 150
```

Pass the string directly to `chart.render(syntax)`. During streaming, send the full accumulated Syntax buffer on each update; see [streaming rendering](/docs/streaming).

## Values and nesting

- Write a property as `key value` or `key: value`.
- Use `-` for array items and indentation for their properties.
- Quote text containing spaces. Quoted values stay strings, including `"2026"` and `"true"`.
- Indent `children` under its parent item for hierarchical charts.
- Put visual overrides under `style`; keep data and layout options at their documented level.

```text
vis mindmap
data
  - name "Project plan"
    children
      - name Research
        children
          - name "Market analysis"
          - name "Feasibility study"
      - name Development
```

## Chart-specific data shapes

Different charts use different field names. For example, line charts use `time` and `value`; bars and columns use `category` and `value`; network graphs use `nodes` and `edges`.

```text
vis dual-axes
categories
  - "North America"
  - "Southeast Asia"
  - Europe
series
  - type line
    name Revenue
    data
      - 100
      - 120
      - 90
  - type column
    name Units
    data
      - 50
      - 60
      - 45
```

Use the [chart reference](/docs/charts) to find a complete example for your data shape.

## Text summaries

Summary uses T8 text syntax, rather than ordinary chart JSON. Pass the text to `render()` and use the constructor’s theme configuration for its appearance. See [Summary examples](/examples/summary).

## Themes and local styles

Pass a reusable theme configuration to the constructor for report-wide styling. Put an individual chart’s supported overrides in its `style` field. See [themes](/docs/themes) and [chart styling](/docs/styles).

## Annotations

Supported charts accept an `annotations` array in JSON or the equivalent nested Syntax. Keep calculation options outside annotation `data`; see [annotation configurations and chart support](/docs/annotations). Summary can also accept `{ type: "summary", text, annotations }` when text highlighting is needed; its `text` remains T8.

```text
vis line
data
  - time 1
    value 20
  - time 2
    value 50
  - time 3
    value 30
annotations
  - type mean
  - type thresholdY
    threshold 40
```

## Start with one annotation

```json
{
  "type": "line",
  "data": [
    { "time": 1, "value": 20 },
    { "time": 2, "value": 50 },
    { "time": 3, "value": 30 },
    { "time": 4, "value": 70 }
  ],
  "annotations": [{ "type": "mean" }]
}
```

The mean uses the chart’s existing `value` mapping. It draws a dashed reference and supplies a default label; you do not need to calculate the result first.

## Configuration rules

- `type` chooses the annotation. The public TypeScript entry is `Annotation<T>`, where `T` is an original data row.
- `data` identifies original rows, positions, or table fields. Use chart data fields, not renderer internals. Object selectors match all supplied fields; arrays select their union without duplicate counting.
- Algorithm options such as `n`, `threshold`, `range`, `p`, `weight`, `minProminence`, and `minDistance` stay outside `data`.
- [`label`](/docs/reference/annotation-options#label) uses the shared label rules: omit it for the analysis default, pass a complete string to replace the text, or pass `""` to hide it.
- [`style`](/docs/reference/annotation-options#annotation-style) uses `AnnotationStyle<Type>` for the fields supported by that annotation. Defaults follow the chart theme; crossing arrows preserve green/red directional meaning. Do not pass internal `shape` or `halo` to point or highlight.
- Prefer one primary emphasis such as `topN`, `group`, or `thresholdHighlight` per chart, optionally combined with reference lines or ranges. Style precedence between different emphasis types on the same marks is not a supported contract.

Logical X/Y refer to data mappings before transposition: line/area use `time/value`, column/bar use `category/value`, and scatter uses `x/y`. On a horizontal bar chart, logical Y is the horizontal numeric axis. Pie uses `category/value`.

```typescript
import type { Annotation } from '@antv/gpt-vis';

type Row = { time: number; value: number };
const annotations: Annotation<Row>[] = [
  { type: 'topN', n: 2 },
  { type: 'thresholdY', threshold: 40, label: 'Reference' },
];
```

## Selection, ranking, and peaks

- `maxX/minX` require numeric or ISO-date X values, not arbitrary category names. `maxY/minY` operate on finite numeric values. All tied extrema are selected.
- `first/last` use filtered input order, not coordinate order or selector-array order. Multiple series use the overall first/last candidate.
- `topN/bottomN` require a positive integer `n`; ties preserve input order and at most `n` items are selected. Multiple series rank together unless `data` selects a series first. Default labels show each rank, including inside pie sectors.
- `peak/valley` work only on ordered line/area series. `minProminence` defaults to 0 in original value units; `minDistance` defaults to 1 observation, not time or pixels. Each series is detected separately using original values, not a stacked cumulative boundary. Missing/nonfinite values break sequences; endpoints are excluded. Flat plateaus use their midpoint, rounded toward the earlier observation. Detect first, then filter results with `data`.

To customize Top N, pass a complete `label` string, or hide all rank labels with `label: ""`. For distinct custom text per item, provide separate explicit `highlight` annotations.

```json
[
  { "type": "topN", "n": 2, "data": { "group": "Actual" }, "label": "Key result" },
  { "type": "peak", "minProminence": 10, "minDistance": 3 }
]
```

## Thresholds and intervals

`thresholdX/thresholdY` draw reference lines only. `thresholdHighlight` also changes the original geometry: line segments change color across the threshold; area, column, and bar fill changes only for the exceeding portion; scatter and table select matching observations. `direction` is `"above"` by default or `"below"`; `inclusive` defaults to false. Line/area `data` must select complete series. Thresholds are finite numbers.

`rangeX/rangeY` only draw intervals, with the other axis spanning the plot. Boundaries must share a type; numeric bounds must be finite and ordered, and strings must identify axis categories or time positions. `rangeInside/rangeOutside` also select observations by their numeric values: inside includes endpoints and outside is strict. Statistical charts include the reference band; tables only emphasize selected rows/cells.

```json
[
  { "type": "thresholdHighlight", "threshold": 40, "direction": "below", "inclusive": true },
  { "type": "rangeX", "range": [2, 4] }
]
```

## Outliers, series, and contribution

`outlier` uses strict IQR fences: values outside `[Q1 − factor × IQR, Q3 + factor × IQR]`, using R-7 quartiles. `factor` defaults to 1.5 and must be positive and finite. Each candidate series needs at least four finite values. Scatter checks Y only, not spatial distance; this is not seasonal or contextual anomaly detection. Use `highlight` when an external algorithm has already chosen the targets.

`group` only accepts `{ "group": "Actual" }` or an array of complete series names. A series mapping must exist; column/bar also require `group: true` or `stack: true`. Each selected series gets its name and color swatch by default, without a leader. A custom `label` replaces these with one shared explanation; `label: ""` hides it. This does not cluster observations; use `highlight` for pie/table selections and network nodes/edges.

`contribution` sums the selected observations, deduplicates overlapping selectors, and divides by the sum of **all input observations**, not the selected subset. Values must be nonnegative and additive; a zero total produces no annotation. Do not supply `total` or `share`. Pie reuses a visible native percentage for a single contribution item where possible, avoiding duplicate labels.

Contribution uses one aggregate bracket and one combined label: above columns, lines, areas, and scatter selections; to the right of bars and selected table rows. The bracket spans the first to last visible selected item without individual leaders. Statistical charts dim unselected observations to 16% of their original opacity; `style.dimOpacity` overrides this. Multiple emphasis annotations keep the union of their targets at their original opacity and lay out their labels together.

Pie contributions use outer arc brackets: adjacent selected slices merge, while separated selections keep separate arcs and share one combined explanation. Unselected slices are never included in an arc. Highlight preserves original colors and borders by default, with unselected items at 16% of their original opacity. Explicit `style.stroke`, `style.lineWidth`, and `style.dimOpacity` still apply. Data label outlines remain independent of shape emphasis.

## Statistics, targets, and events

`mean/median/quantile` use finite values on `axis`, default `"y"`; `data` can restrict candidates. An empty set produces no annotation. `p` is required for quantile and lies in [0, 1], using R-7 interpolation. Axis references are dashed by default and follow theme text color; an explicit `style.stroke` wins.

`target` accepts either a finite `target` value (`axis` defaults to `"y"`) or `data` containing at least two complete positions for a changing baseline. Do not supply both.

`event` defaults to `axis: "x"` and accepts one/multiple axis positions or selectors that uniquely identify a row. It draws event lines and labels; it does not detect change points.

```json
[
  { "type": "quantile", "p": 0.95, "data": { "group": "Actual" } },
  {
    "type": "target",
    "data": [
      { "time": 1, "value": 30 },
      { "time": 4, "value": 60 }
    ]
  },
  { "type": "event", "data": [{ "time": 2 }, { "time": 4 }], "label": "Campaign" }
]
```

## Scatter regions and centers

`quadrant` requires both numeric axis dividers in `data`. `labels` overrides `topRight`, `topLeft`, `bottomLeft`, and `bottomRight`; set a name to `""` to hide it. `label` controls the two divider labels; `label: ""` hides all text.

`centroid` computes the arithmetic center of valid numeric pairs. `weight` names an original data field for a weighted center; weights must be finite and nonnegative with a positive total. The center is a calculated position, shown as a cross with no halo by default; `pulse: true` opts into one.

```json
[
  {
    "type": "quadrant",
    "data": { "x": 3, "y": 40 },
    "labels": {
      "topRight": "High investment / high return",
      "topLeft": "Low investment / high return",
      "bottomLeft": "Low investment / low return",
      "bottomRight": "High investment / low return"
    }
  },
  { "type": "centroid", "weight": "weight" }
]
```

## Crossings

For a threshold, supply a finite `threshold` and optionally select one series with `data`. For two-series intersections, omit `threshold` and supply exactly two nonoverlapping selectors in `data.series`. Direction compares the first selected series against the second: `"up"`, `"down"`, or `"both"` (default).

Only unstacked line/area is supported. Native curve shapes may be `line`/`linear`, `smooth`, `hv`, `vh`, or `hvh`; other curve shapes are rejected. Every series needs unique X values and numeric X must be monotonic. Numeric series are compared in their shared domain without extrapolation; categorical X uses the actual observation following a crossing, not a fabricated intermediate category. Missing values break paths. Touching and returning to the same side is not a crossing; an equal-value plateau that switches sides uses its first equal observation.

Triangles use fixed green/red directional colors, adjusted for dark backgrounds. On area charts, the annotation avoids an additional colored fill over the existing area.

```json
[
  { "type": "crossing", "threshold": 40, "direction": "down" },
  { "type": "crossing", "data": { "series": [{ "group": "Actual" }, { "group": "Budget" }] } }
]
```

## Drawing primitives

These six capabilities draw caller-specified positions or emphasize existing content; they do not infer analysis results.

| type        | Minimal configuration                                                   | Conditions                                                                  |
| ----------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `path`      | `{"type":"path","data":{"value":40}}`                                   | One axis value spans the plot; ordered arrays connect at least two anchors. |
| `range`     | `{"type":"range","data":{"value":[20,60]}}`                             | Only axis fields; omitted axes span the plot.                               |
| `point`     | `{"type":"point","data":{"time":2,"value":50}}`                         | One or multiple independent markers; pulse defaults to animated.            |
| `connector` | `{"type":"connector","data":[{"time":1},{"time":4}],"label":"Compare"}` | Exactly two anchors; shape line, curve, dimension, or bracket.              |

| `highlight` | `{"type":"highlight","data":{"time":2}}`                                | Select existing content; no new data point is inferred.                     |

All six support line, area, column, bar, and scatter. Network graph supports path, point, connector, text, and highlight; graph paths require anchor arrays. Pie, table, and summary support highlight only among these primitives. Other relationship/hierarchy charts are not yet integrated.

For positions, complete axis fields specify independent coordinates; other selectors must identify a unique row. Network anchors use original node fields such as `name`; edge highlights can select original `source` and `target` fields. `connector.orientation` is `"horizontal"` or `"vertical"` for dimension/bracket; it controls the comparison span.

## Table and summary targets

For table `highlight`, `data.row` selects rows and `data.column` optionally limits emphasis to a column; column alone emphasizes the whole column. Calculation annotations require `data.field`, with optional candidate `row` and destination `column`. These are table mappings, not chart-wide field overrides. Contribution requires `row` and keeps all rows in its denominator.

```json
{
  "type": "table",
  "data": [
    { "product": "Basic", "revenue": 20 },
    { "product": "Pro", "revenue": 60 },
    { "product": "Team", "revenue": 40 }
  ],
  "annotations": [{ "type": "topN", "n": 1, "data": { "field": "revenue", "column": "revenue" } }]
}
```

Summary accepts T8 text, or `{ type: "summary", text, annotations }` when external highlights are needed. `data.text` must be nonempty and uniquely match visible text; it can span T8 inline fragments. Theme configuration goes in the constructor.

```json
{
  "type": "summary",
  "text": "Revenue reached [240](metric_value).",
  "annotations": [{ "type": "highlight", "data": { "text": "240" }, "label": "Revenue" }]
}
```

## How overrides work

Appearance is resolved in this order, with later values taking priority:

**Built-in defaults → tokens → shared style → chart-specific style → per-render style**.

Nested objects merge; arrays replace. A `theme` in the render configuration takes priority over the constructor theme. This lets an individual chart choose a different appearance. Summary uses its constructor theme with T8 text and has no per-render style object.

A fixed `style.node.fill` takes priority over the palette, including under the theme’s `charts` overrides. Remove that fill when relationship nodes should keep different category colors. Shared stroke, radius, and label settings can still be used.
